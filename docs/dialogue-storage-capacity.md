# 对话句子记忆容量与迁移验证

测量日期：2026-10-08。证据来自 `scripts/dialogue-memory-storage.test.ts` 的完整课程容量回归；这里不保存学习者草稿或备份正文。

## 测量方法

从 `public/immersion/week-01.json` 到 `week-26.json` 读取新内容原句，排除复习副本，以原始 `lessonId + lineId` 去重，并纳入补缺场景。当前共 **8029 个稳定句子 ID**；这是最终生成课程的实际数量。7,333和7,741条均为此前容量测量的历史快照。

分别构造每句 1、4、8 次自评反馈的记录。草稿采用对应原句的实际长度，并交替加入小幅变化，检查历史草稿与当前草稿分别保存。模拟包含曝光、先写后反馈、反馈后揭晓、到期后 37 分钟的回忆、不同毫秒时间和第 8 次提前练习。每次反馈使用项目调度函数生成证据，未手工缩短字段。它是容量与无损还原用的模拟，不是学习者成绩或自然语言准确率测量。

| ------------ | -----------------: | ---------------: | ---------------------: | -------------------------------: |
| 1            |          5,424,424 |        1,311,176 |              1,671,472 |                        2,622,352 |
| 4            |         10,723,703 |        2,626,566 |              3,002,970 |                        5,253,132 |
| 8            |         17,810,819 |        4,521,410 |              4,897,814 |                        9,042,820 |

包含课程备份外层封装、JSON 字符串转义后的 **8 次完整备份为 4,946,100 UTF-8 字节**。其他词汇、写作、设置等记录会在实际备份中增加文件大小。

UTF-16 估算为字符数乘 2，用于发现 localStorage 的容量风险；浏览器具体配额和计费方式可能不同。即使紧凑格式，8 次记录仍超过常见 5 MiB 的 localStorage 总预算，因此仅扩大备份文件限制不能解决日常保存问题。

## 保存与备份格式

- 浏览器句子记录保存到 IndexedDB 数据库 `korean-dialogue-memory-v1` 的 `sentences` store，每个稳定句子 ID 一条记录。输入草稿按句读取、按句写入，无须每个键盘事件序列化全课程。
- 数据库存储保留可验证的对象结构。备份使用 `serializeDialogueMemory` 的 v2 紧凑数组格式：记录内复用时间与草稿，重复草稿只存一次，接近当前草稿的历史文本可存无损前后缀差分。证据中的独立与延迟回忆标记由保留的反馈、草稿、揭晓及时间字段重新验证。
- `parseDialogueMemoryStrict` 与宽松读取器同时接受旧对象格式及紧凑 v2。严格导入会拒绝损坏字段、索引与差分；宽松读取不会把损坏条目当成有效学习证据。相同稳定 ID 不会因复习场景变化生成重复记录。
- 历史尝试仍遵守原有每句最近 20 次证据的上限，累计反馈计数另行保存。本次压缩没有进一步截断历史或丢弃当前草稿。
- 浏览器备份包含 IndexedDB 句子记录以及原有课程 localStorage 数据；导入不把完整句子记忆重新写回 localStorage。导出、文件解析、直接调用导入时均校验 32,000,000 UTF-8 字节的整体上限。旧对象格式的 8 次记录备份也能导入。

## 迁移与失败保护

1. 严格读取旧 `korean-dialogue-memory-v1` localStorage 副本；损坏时明确失败，不能以空数据覆盖。
2. 在一个 IndexedDB 读写事务内合并全部句子。保留本机已有非空草稿、较新的反馈及调度，不覆盖数据库中更近的进度。
3. 只有整个事务提交成功，并且旧副本仍与迁移前快照相同，才删除旧副本。写入失败、事务中途取消或旧标签页写出新副本时保留旧数据。
4. 同句连续保存使用原生同 store 读写事务的串行规则；读取与写入在同一个事务内完成，时间倒退的写入会拒绝。只有提交成功才发送更新事件。
5. 导入先读取检查迁移，再应用本地课程记录与数据库合并。数据库事务失败会回滚该事务的全部句子，并恢复本次改写的本地记录；等待期间其他标签页写入的新值会保留。

IndexedDB 同样可能遇到浏览器配额、隐私设置或设备清理。失败会返回明确状态；不会把未提交的写入报告为已保存。本测量没有宣称所有设备都提供相同配额，用户仍需定期下载备份。

## 可复核回归

```sh
npx tsx --test scripts/dialogue-memory.test.ts scripts/dialogue-memory-storage.test.ts scripts/study-records.test.ts
npx tsc --noEmit --incremental false
```

数据库回归使用 `fake-indexeddb` 的 IndexedDB API 和事务语义：实际执行请求成功后取消事务，验证已执行的写入也完整回滚。覆盖旧数据迁移、失败后的原副本保留、损坏拒绝、两连接连续保存、导入失败恢复以及等待期间其他标签页的新写入保护。

完整容量测试将 8029 句、每句 8 次反馈实际写入测试数据库，导出紧凑备份，再导入另一新数据库；对全部记录逐字段深度相等比较，并再次导入大于旧 8M 字符上限的旧对象备份。三种反馈次数均验证紧凑与旧格式无损还原。测试结果会输出上述数量与大小；课程增加后应以重新运行的数值为准。
